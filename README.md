# Movie recommendations — reproducible baseline

Базовый проект для задачи рекомендаций фильмов по истории взаимодействий. Реализован прозрачный baseline глобальной популярности, Recall@10, leave-last-out validation и генерация `submission.csv`.

## 1. Структура данных

Поместите в `data/`:
- `events.csv` — обязательные `user_id`, `item_id`; опционально `rating`, `timestamp`.
- `user_features.csv` — опциональные признаки пользователей.
- `item_features.csv` — опциональные признаки фильмов.
- `submission_sample.csv` — пример требуемого формата.

Если в датасете названия столбцов отличаются, измените их в коде или добавьте соответствующие алиасы. Не коммитьте приватные/ограниченные данные, если правила курса это запрещают.

## 2. Установка и запуск

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
make run
```

На Windows активируйте окружение командой `.venv\\Scripts\\activate`.

`make run`:
1. создаёт `reports/eda.md`;
2. запускает leave-last-out валидацию и сохраняет предсказания;
3. создаёт `submission.csv`.

## 3. Отдельные команды

```bash
python -m src.eda --data-dir data --out-dir reports
python -m src.run_validation --data-dir data
python -m src.run_validation --data-dir data --positive-mode threshold --threshold 4
python -m src.run_validation --data-dir data --half-life-days 180
python -m src.make_submission --data-dir data --sample data/submission_sample.csv --output submission.csv
```

Порог 4 — только проверяемая гипотеза, а не универсально правильное определение позитива. Проверьте его на валидации.

## 4. Методика

- Leave-last-out удерживает последнее уникальное взаимодействие каждого пользователя с минимум двумя уникальными фильмами.
- Если есть timestamp, он используется для сортировки; иначе используется порядок строк в файле, который не обязательно отражает время.
- `Recall@10` считается как macro-average по пользователям с целевым событием.
- В рекомендациях исключаются фильмы, уже присутствующие в train-истории пользователя.
- Все ID в итоговом CSV записываются строками.

## 5. Ограничения, которые нужно проверить

1. Валидация должна соответствовать реальному протоколу теста. Если тест — временной срез, замените leave-last-out на global temporal split.
2. Для порога позитива важно согласовать цель оценки с организаторами. Реализация threshold-валидации использует последние позитивные события как цели, а все события пользователя — как историю, кроме удержанного целевого item.
3. Если в `submission_sample.csv` заданы конкретные пары user-item или фиксированное число строк на пользователя, адаптируйте генератор после проверки схемы файла. Текущая реализация предполагает, что sample задаёт список пользователей и требуемые имена столбцов.
4. Этот baseline не использует `user_features.csv` и `item_features.csv` в рекомендациях; EDA выводит их схему и пропуски. Следующий эксперимент — персонализация или collaborative filtering.
5. Если у пользователя меньше 10 unseen items, baseline выдаёт меньше 10 строк, не создавая вымышленных item ID. Это следует проверить на данных и при необходимости дополнить допустимыми кандидатами.

## 6. Эксперименты

Все результаты фиксируйте в `EXPERIMENTS.md`. Не вписывайте ожидаемые метрики вместо реально полученных.
